# 柔性手套无线手势控制器 —— 代码说明文档

> 主机采集柔性手套的 5 路弯曲信号 → 串口/LoRa 发帧 → 从机按帧内容控制输出开关（GPIO）。
> 本文档对应工程根目录下的三个子工程：

| 工程 | 目录 | 板子 | 角色 |
|---|---|---|---|
| 主机 | `master\` | STM32G030K8T6 | 采集手套 + 按键标定 + 发帧 |
| 从机 | `slave(v2)\` | STM32G030K8T6（同款板） | 收帧 + 开/关输出 |
| HC-12 配置工具 | `ChangeId\` | STM32G030K8T6（同款板） | 把 HC-12 模块改成 4800 / 频道 C002（见 §9） |

> 版本：**多手指控制版本**

---

## 1. 硬件与接线

### 1.1 板子（主机 / 从机同款）

| 功能 | 引脚 | 说明 |
|---|---|---|
| 手套信号 CH1~CH5 | **PA2 / PA3 / PA4 / PA5 / PA6** | 板上丝印 CH1~CH5，对应 ADC1_IN2~IN6；每路都**并了一个 100Ω 电阻到 Vin** |
| 串口 | **PA9 = TX，PA10 = RX** | USART1，**4800 8N1**，主机从机要一致 |
| 烧录/调试 | PA13 / PA14 | SWD（保留，不要当普通 IO） |
| 板载蓝灯 | **PB8** | 低电平点亮（VCC3V3→LED→1K→PB8） |
| 按键 | **PA0** | 标定按键，另一端接 GND（按下 = 低电平） |
| 从机输出 | **PA6** | 普通 GPIO 推挽输出（板子丝印 CH5 网络），高电平="亮" |

### 1.2 柔性手套的电气特性（重要）

- **弯曲 → 电阻变大 → 该通道电压升高 → 主机读到的 mV 变大**。
- 5 路分别接在 CH1~CH5（经 P2 排针或直接焊线）。
- 每路的实际量程取决于手套本身和接线方式（有没有串分压电阻等），
  所以**门限不要写死，用按键标定**（见 §4.4）。
- ⚠️ CH1~CH5 上的 100Ω 是接到 **Vin**（LDO 输入，电池 3.7~4.2V 或 5V）的：
  - 当输入用（主机）：通道电压会被这 100Ω 抬向 Vin，手套的分压结果要以实测为准；
  - 当输出用（从机 PA6）：低电平期间会有 `Vin/100Ω` 的电流灌进引脚（5V→50mA），
    **超过 STM32 单脚 20mA 的推荐值**，建议把 CH5 那个 100Ω（丝印 R7）**拆掉**。

## 2. 通信协议

主机 → 从机，**每帧固定 3 字节**：

| 字节 | 内容 | 说明 |
|---|---|---|
| 1 | `0xCC` | 帧头 |
| 2 | `bits` | **5 路全发**：bit0=CH1、bit1=CH2、bit2=CH3、bit3=CH4、bit4=CH5（1 = 该通道超过门限，判定为弯曲；0 = 伸直）；bit5~bit7 恒为 0 |
| 3 | `0xEE` | 帧尾 |

- 串口参数：**4800 8N1**，无流控。
- 发送节奏（主机）：**状态一变立刻发**；状态不变也至少 **200ms** 发一帧保底；
  两次发送之间至少隔 **20ms**（防止读数抖动时猛发）。
- 从机对 `bits` 的解释（见 §4.3）：
  - **数 `bits` 的二进制里有几个 1：`1 的个数 ≥ 3` → 输出"亮"（PA6 亮电平 + 板载蓝灯 PB8 亮）**；
  - **`1 的个数 0~2` → 输出"灭"**。
  - 这个门限就是 `slave(v2)` 里的宏 **`BITS_ON_MIN`（当前 3）**，改成 2 或 4 就能整体调整灵敏度。

举例：

| 手套状态 | bits 的值 | 二进制 | 1 的个数 | 从机 PA6 | 从机蓝灯 PB8 |
|---|---|---|---|---|---|
| 都不弯 | 0x00 | 00000 | 0 | 灭 | 灭 |
| 只弯 CH4 | 0x08 | 01000 | 1 | 灭 | 灭 |
| CH4+CH5 都弯 | 0x18 | 11000 | 2 | 灭 | 灭 |
| CH2+CH4+CH5 弯 | 0x1A | 11010 | 3 | **亮** | **亮** |
| CH1+CH2+CH3 弯 | 0x07 | 00111 | 3 | **亮** | **亮** |
| 五指全弯 | 0x1F | 11111 | 5 | **亮** | **亮** |

> ⚠️ 关键前提：**CH1~CH3 出厂门限是 8000mV（等于禁用，永远判 0）**，
> 所以不标定的话最多只有 CH4/CH5 两位能变 1，**永远达不到 3 个 1，灯永远不亮**。
> 想用"≥3 个 1"的判定，必须先用 PA0 把 **CH1~CH3 也标定**（见 §4.4 / §5.2）。

## 3. 主机代码结构（`master\Core\Src\main.c`）

### 3.1 采集：ADC 5 通道 + DMA（`ADC1_Init_5CH_DMA()`）

- ADC1 配成 **5 个规则通道**（rank1~rank5 = IN2~IN6），**连续转换**；
- DMA1_Channel1 **循环模式**，把 5 个通道的结果不停搬进 `adc_dma_buf[5]`；
- **不用中断**：一帧只要约 8.5µs，若开 DMA 完成中断会有 100kHz+ 的中断频率，纯属浪费 CPU；
- 主循环随时用 `ADC_GetFrame()` 取"最新一帧"，不触发转换、不等待。

> 注：CubeMX 里 ADC1 目前只勾了 1 个转换，这段在 `USER CODE` 区把它重新配成 5 通道，
> 即使以后在 CubeMX 里补齐，重复配置也是幂等的。

### 3.2 电压换算与判定（主循环第 2 步）

```c
adc_mv[i] = adc_raw[i] * 3300 / 4095;          /* 原始值 -> mV（12bit，VDDA=3.3V） */

low_th = glove_off[i] - GLOVE_HYST_MV;         /* 迟滞 40mV，防抖 */
if      (adc_mv[i] > glove_off[i]) glove[i] = 1;   /* 高于门限：弯曲 */
else if (adc_mv[i] < low_th)       glove[i] = 0;   /* 低于 门限-40mV：伸直 */
/* 中间死区内：保持上一次状态不变（避免灯在门限附近来回跳） */
```

### 3.3 组帧与发送（主循环第 3 步）

```c
/* 把 5 路状态打包进一个字节：bit0 = CH1 … bit4 = CH5 */
bits = (glove[0] | (glove[1] << 1) | (glove[2] << 2) | (glove[3] << 3) | (glove[4] << 4));

if ((bits != last_sent_bits) || (now - last_send_tick >= 200ms))   /* 变化即发 / 保底 200ms */
    if (now - last_send_tick >= 20ms)                              /* 最小间隔，防抖 */
        发送 CC bits EE;
```

- 标定过程中（`key_stage != 0`）强制发 `bits = 0`（从机灯灭），避免用旧门限乱闪。
- 5 路都会被采集、判定、标定，也都发出去；从机自己数 `1` 的个数来决定亮灭。

### 3.4 按键标定（PA0，按 3 次）

| 第几次按下 | 手套动作 | 代码行为 | 串口打印 |
|---|---|---|---|
| 第 1 次 | **五指伸直**，按住不放 | 20ms 采 1 次 × 10 次求平均 → `adc_avg1[]` | `KEY1 avg: 1500 1240 1690 1810 1660 (mV)` |
| 第 2 次 | **五指弯曲**，按住不放 | 同上 → `adc_avg2[]` | `KEY2 avg: 1600 1250 1700 1800 1660 (mV)` |
| 第 3 次 | （松手即可） | `glove_off[i] = (avg1+avg2)/2` | `KEY3 off:1550 1245 1695 1805 1660 ok=5` |

- **标定有效性检查**：若某通道两次采样的差 `< GLOVE_CAL_MIN_DIFF_MV (100mV)`，
  说明两次是同一个姿势，这一路**保留原门限不修改**，`ok=` 后面会告诉你成功了几路。
- 第 3 次按完自动回到"第 1 次"，可以随时重新标定。
- 每次按下的采样耗时约 **10×20ms = 200ms**，所以按键要按够 200ms 以上再松手。

### 3.5 出厂初值与上电行为

```c
static uint16_t glove_off[ADC_CH_NUM] = {8000, 8000, 8000, 1650, 1850};  /* mV */
```

- `8000mV` 高于 ADC 量程上限（3300mV）→ 该通道**永远不会判定为弯曲**，
  这是"未标定 = 先禁用"的占位值。当前只有 **CH4=1650mV、CH5=1850mV 是可用门限**，
  所以**上电后建议先用 PA0 把 5 路都标定一遍**（尤其 CH1~CH3，否则它们恒为 0，
  从机"≥3 个 1"的判定就永远达不到）。
- 上电串口打印 `glove ready`。
- 板载蓝灯 PB8 每 **500ms** 翻转一次，表示程序在跑（和上报解耦）。

### 3.6 主机主循环流程

```
while (1)
{
    ① 每 10ms 扫一次 PA0，检测到按下 -> key_on_press()（第1/2/3次分别采样/算门限）
    ② 读一帧 ADC -> 换算 mV -> 带迟滞判定 5 个通道 -> 5 路打包成一个 bits（bit0=CH1…bit4=CH5）
    ③ 需要发就发：CC bits EE（变化即发 / 200ms 保底 / 最小间隔 20ms）
    ④ PB8 每 500ms 翻一次（心跳）
    HAL_Delay(10);
}
```

## 4. 从机代码结构（`slave(v2)\Core\Src\main.c`）

### 4.1 接收：环形缓冲 + DMA（`uart1_rx_dma_init()` / `rx_start()`）

- 因为 CubeMX 里没配串口 DMA，**这套在代码里自己配**：
  DMA1_Channel2（G030 只有 Channel1~3，Channel1 被 ADC 占了），
  `DMA_REQUEST_USART1_RX`，字节、内存递增、**循环模式**；
- 缓冲区 `rx_ring[32]`，**只挂一次** `HAL_UART_Receive_DMA()`，之后一直收；
- DMA 中断被显式关闭，主循环用 `__HAL_DMA_GET_COUNTER()` 查"收到了多少字节"。

### 4.2 解析：字节流状态机（`rx_poll()`）—— 为什么不用"一次收 3 字节"

早期版本是"挂 DMA 收固定 3 字节 → 处理 → 再挂 3 字节"。**这个写法有个致命缺陷**：
如果挂上去的瞬间正好卡在主机某一帧中间，收到的就是 `[data][EE][CC]`，
校验失败后**再挂还是 3 字节**，偏移量 1 字节就永远保持下去，再也收不到合法帧
（现象：`rx_frame[1]` 一直是 `0xEE`；主机比从机晚开机、或主机标定时打印 ASCII 都会触发）。

现在的写法：

```
字节流 → [找 0xCC 帧头] → [收 1 字节 data] → [等 0xEE 帧尾]
              ↑                                   │
              └──── 不是 0xEE 就重新找帧头 ←───────┘
```

- 只有收到 `0xCC` 才认帧头、只有收到 `0xEE` 才认帧尾，中间任何杂字节（包括主机标定的
  ASCII 打印，ASCII 都 < 0x80 不会误判）都会被丢掉；
- 所以**主机什么时候开机都无所谓，最多丢一帧就自动重新对齐**；
- 帧尾位置收到 `0xCC` 时会把它当作下一帧的帧头（少丢数据）。

### 4.3 输出：PA6 普通 GPIO 开关（`out_gpio_init()` / `out_write()`）

- PA6 配成**普通推挽输出**（不再用 PWM/TIM3）：
  上电先输出"灭"，之后每收到一个合法帧就按"data 里 1 的个数"刷新。

```c
/* 初始化 */
gpio.Pin = GPIO_PIN_6; gpio.Mode = GPIO_MODE_OUTPUT_PP; gpio.Pull = GPIO_NOPULL;
HAL_GPIO_Init(GPIOA, &gpio);
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_6, OUT_OFF_LEVEL);      /* 上电"灭" */

/* 收到合法帧时：数 data 里有几个 1（bit0=CH1 … bit4=CH5） */
if (bit_count(data) >= BITS_ON_MIN) { out_write(1); out_led(1); }   /* ≥3 个 1 -> 亮 */
else                               { out_write(0); out_led(0); }   /* 0~2 个 1 -> 灭 */
```

| 收到的 data（合法帧） | PA6 输出 | 板载蓝灯 PB8 |
|---|---|---|
| **`1` 的个数 ≥ 3**（如 `0x1A`、`0x07`、`0x1F`） | **"亮"电平**（默认高） | **亮** |
| `1` 的个数 0~2（都不弯 / 只弯一路 / 只弯两路） | **"灭"电平**（默认低） | 灭 |
| 帧头/帧尾不对 / 一直没收到帧 | **保持上一次状态不变** | 保持不变 |

- `bit_count()` 用的是 Kernighan 法（`v &= v-1` 每轮消掉一个 1），5 位数据最多循环 5 次，开销可忽略。

- 极性宏（`main.c` 顶部）：
  - `OUT_ON_LEVEL` / `OUT_OFF_LEVEL`：PA6 的"亮/灭"电平，默认 **高=亮**；
    如果 PA6 上接的灯是低电平点亮，把这两个宏对调；
  - `LED_ON_LEVEL` / `LED_OFF_LEVEL`：板载蓝灯（低电平点亮）。

### 4.4 上电行为

| 时刻 | 表现 |
|---|---|
| 上电 | 板载蓝灯快闪 **3 下**（自检：确认新固件在跑），随后停在"灭"；PA6 输出"灭" |
| 收到合法帧 | 按"data 里 1 的个数是否 ≥ `BITS_ON_MIN`"刷新 PA6 和蓝灯 |

### 4.5 从机主循环流程

```
while (1)
{
    rx_poll();      /* 把 DMA 环形缓冲里新到的字节喂给状态机；
                       收到合法帧 CC data EE 就数 data 里 1 的个数：
                         >= 3 个 1 -> PA6 输出"亮" + 蓝灯亮
                         否则      -> PA6 输出"灭" + 蓝灯灭            */
}
```

## 5. 操作步骤

### 5.1 编译与烧录

- 用 **Keil MDK** 打开各自工程：
  - 主机 `master\MDK-ARM\main.uvprojx`
  - 从机 `slave(v2)\MDK-ARM\main.uvprojx`
  - HC-12 配置工具 `ChangeId\MDK-ARM\main.uvprojx`
- 生成目标选对应 MCU（STM32G030K8），编译后下载（SWD：PA13/PA14 + GND + 3V3）。

### 5.2 主机标定（每次上电/换手都要做）

1. 串口助手接主机的 **PA9(TX)**（USB-TTL），**4800 8N1**；上电应看到 `glove ready`。
2. **五指伸直**（保持不动），按一下 PA0 并按住 200ms 以上 → 串口出现 `KEY1 avg: ...`。
3. **五指弯曲**（保持不动），按第二下 → 出现 `KEY2 avg: ...`。
4. 松开，按第三下 → 出现 `KEY3 off: ... ok=N`。
   - 每路弯曲/伸直的电压差应 ≥100mV，差值太小那一路不会被标定（`ok` 数会少）。
5. 之后做手势：**任意 ≥3 路同时弯曲**时，从机的灯就会亮（只弯 1~2 路是灭的）。
   - 注意 CH1~CH3 默认门限 8000mV（禁用），所以**第 2、3 步的五指伸直/弯曲标定必须做**，
     否则只有 CH4/CH5 两路能变 1，永远达不到 3 个 1。

### 5.3 从机验证

- 从机 **PB8（板载蓝灯）**：让 **≥3 路同时弯曲**（例如 CH1+CH2+CH3，或 CH2+CH4+CH5）→ 亮；
  松到只剩 2 路及以下 → 灭。
- 从机 **PA6**：同一个条件 —— ≥3 路时输出高电平（3.3V），否则低电平（0V）。
  用万用表直接量 PA6 对 GND 的电压即可（≈3.3V = 亮，≈0V = 灭）；
  接负载的话：LED 串 1kΩ 到 GND（高电平点亮），或接继电器模块的输入端。

### 5.4 联调检查表

| 现象 | 先查什么 |
|---|---|
| 从机灯一直不亮 | 是不是真的 ≥3 路弯到门限之上；CH1~CH3 是否还是 8000（没标定就永远凑不够 3 个 1）；量一下从机 PA6 电压有没有变 |
| 从机灯常亮不灭 | 门限标定得太低（把"伸直"也判成了 1），3 路以上一直是 1；重新标定 |
| 从机 PB8 上电不闪 3 下 | 固件没烧进去 / 没复位 |
| PA6 一直是 0V | 主机 `KEY3` 后 `ok=0`（没标定成功）；或同时弯的路数不够；或帧没收到 |
| 某个通道没反应 | 该通道 `glove_off` 还是 8000（没标定成功）；或手套那一路接触不良 |

| `uart1_rx_dma_init()` | 配 DMA1_Channel2 循环接收 + NVIC |
| `RX_DMA_IRQHandler()` | DMA 中断入口（本方案用不到，留着备用） |
| `rx_start()` | 挂一次接收（之后一直收），顺带关掉 DMA 中断 |
| `rx_poll()` | 取新字节 → 状态机解析 → 合法帧按"1 的个数 ≥ `BITS_ON_MIN`"刷新 PA6 和蓝灯 |
| 主循环 | `rx_poll()` |

## 8. 已知注意事项（都是踩过的坑）

1. **CH1~CH5 上的 100Ω 到 Vin**
   - 主机当输入用：通道电压会被这 100Ω 影响，读数以实测为准（所以必须标定）；
     如果 Vin 是 5V，通道上可能出现 >3.3V 的电压，长期对 IO 不好，建议确认接线。
   - 从机 PA6 当输出用：低电平期间 `Vin/100Ω` 的电流会灌进引脚（5V→50mA，超规格），
     **建议把 CH5 的 100Ω（R7）拆掉**。
2. **主机门限必须标定**：初值 `{8000,8000,8000,1650,1850}` 里的 8000 是"禁用"占位值，
   **CH1~CH3 不标定就恒为 0** —— 而从机的判定是"≥3 个 1 才亮"，
   所以不标定就永远凑不够 3 个 1，灯一定不亮。上电务必走一遍 §5.2 的三次按键标定。
3. **主从波特率必须一致**：当前都是 **4800**。
4. **主机标定会往串口打 ASCII**（KEY1/KEY2/KEY3），从机的状态机会自动忽略，不影响解析。
5. **从机 PA6 是普通 GPIO 输出**，和 CubeMX 里 `.ioc` 的配置（GPIO_Output）一致；
   代码里 `out_gpio_init()` 只是再配一遍做保险，两边不会打架。
6. **两个工程的外设配置都在 `USER CODE` 区**，CubeMX 重新生成代码不会丢；
   但也因此**不要依赖 CubeMX 界面里的 ADC 配置**（主机 ADC 五通道是代码在运行时配的）。
7. **曾经用过 PWM（TIM3_CH1）输出**，后来按需求改回 GPIO 开关；现在工程里没有任何 TIM 相关代码，
   如果以后想重新用 PWM，需要重新加回 TIM3 的配置（PA6 的 AF1 = TIM3_CH1）。

## 9. HC-12 参数配置工具（`ChangeId\`）

> 作用：把 HC-12 模块的**串口波特率改成 4800、通信频道改成 C002**（和本工程一致），
> 不用电脑串口助手、也不用记 AT 指令，烧一次、上电就自动配好。

### 9.1 接线

| 板子引脚 | 接到 HC-12 |
|---|---|
| PA9 (TX) | 模块 RXD |
| PA10 (RX) | 模块 TXD |
| 3V3 / GND | 模块 VCC / GND（HC-12 是 3.3~5V 供电，和板子共地） |
| **PB4** | 模块 **SET**（工具用代码拉低它进 AT 模式） |

- 模块 **SET 出厂是悬空**的，必须接：接 PB4（推荐，全自动），或者直接接 **GND**。
- 如果 SET 直接接 GND：上电就是 AT 模式、波特率固定 9600，工具照样能配；
  但**配完要把这根线从 GND 上摘掉**（或者改接 PB4 并让程序正常退出），否则模块永远停在 AT 模式不转发数据。
- 天线（A1）接好，配置本身不需要对端，但配完联调时另一端频道必须也是 C002。

### 9.2 自动流程（`hc_configure()`）

```
上电 -> 蓝灯快闪 3 下（开始干活）
     -> PB4 拉低（SET=低 -> AT 模式），等 100ms
     -> hc_find_baud()：依次试 9600/4800/115200/19200/57600/38400/2400/1200，
        谁是 "AT"->"OK" 就用谁（每个波特率给两次机会，防止首条指令被吞）
     -> AT+B4800   （期望回 OK+B4800）
     -> AT+C002    （期望回 OK+C002）
     -> AT+RX      （读回参数，回包留在 hc_rx[] 里，仿真时可以看）
     -> PB4 拉高（SET=高 -> 回到透传模式），等 100ms
```

- **蓝灯常亮 = 配置成功**；**蓝灯熄灭 = 失败**（多半是 SET 没拉低 / TX、RX 接反 / 模块没供电），
  按板子复位键重试即可。
- 想改目标值就改 `main.c` 顶部两个宏，重新编译即可：
  - `HC_BAUD_TARGET`（现在 4800）——注意 `AT+B` 那条指令里的 `"4800"` 字面量也要同步改；
  - `HC_CHANNEL_TARGET`（现在 `"002"`，即 433.4MHz 附近，范围 C001~C127，400kHz 一步）。
- `HC_USE_SET_GPIO` 改 `0` 时程序不碰 PB4（适用于 SET 直接接 GND 的情况）。

### 9.3 一定要知道的两件事

1. **`AT+Bxxxx` 是"下次上电生效"**：配完这一条，模块本次仍用旧波特率说话，
   **必须给模块断电再上电**，新波特率才生效（频道 `AT+Cxxx` 是退出 AT 模式后立即生效）。
2. 配置只在**上电时做一次**，之后主程序就只是把蓝灯点成"成功/失败"，不会再去动模块。

### 9.4 为什么 HC-12 配不到 ATK-LORA-02（顺便记一笔）

- HC-12 是 **Si4438 芯片 + 私有 FSK 调制**，ATK-LORA-02 是 **SX1278 + LoRa（CSS 扩频）**，
  **物理层完全不同**，不是频道/波特率能对上的 —— 两者永远收不到对方的数据。
- 板子上 HC-12 和 ATK-LORA-02 共用同一个天线座（A1），**也不能同时插**，只能二选一。
- 想让两边通信，只能是**同型号对同型号**（HC-12 ↔ HC-12，或 LORA-02 ↔ LORA-02），
  并按 §2 的 3 字节协议改好波特率（4800 8N1）和频道。
